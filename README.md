# fw_test — тест сетевых возможностей файрвола

Скрипт прогоняет большой набор сайтов (RU-сегмент и иностранный сегмент) и
сетевых операций, чтобы понять, **что именно пропускает или режет файрвол**:
DNS, отдельные порты, TLS-хендшейк, исходящие POST, скачивание и отдачу файлов.

- Только стандартная библиотека Python — ничего ставить не нужно.
- Запуск **без прав root**: обычные TCP-соединения и DNS-резолв, никаких
  raw-сокетов, ICMP, iptables или изменений системы.
- Скрипт ничего не пишет в систему, кроме отчётов в папку `--output-dir`.

---

## Состав

| Файл | Назначение |
|------|------------|
| `fw_test.py` | сам скрипт |
| `domains_ru.txt` | 1200 RU-доменов по популярности |
| `domains_foreign.txt` | 5500 иностранных доменов по популярности |

Положите все три файла в одну папку. Скрипт сам подхватит списки доменов;
если файлов нет — используется встроенный сид-список на несколько сотен доменов.

---

## Требования

- Python **3.8+** (проверка: `python3 --version`).
- Исходящий доступ в интернет с тестируемого сервера.
- Прав администратора **не требуется**.

---

## Быстрый старт

```bash
# проверка, что всё работает: 30 RU + 30 иностранных доменов
python3 fw_test.py --limit 30
```

Прогон занимает меньше минуты и сразу печатает сводку в консоль. Если она
выглядит осмысленно — можно запускать полный тест.

---

## Полный прогон

```bash
python3 fw_test.py --workers 60 --timeout 8 --delay 0.02
```

Это проверит все 1200 RU и 5500 иностранных доменов плюс тесты скачивания и
отдачи. Полный прогон — это десятки тысяч исходящих соединений с вашего
сервера, поэтому **первый раз всегда запускайте с `--limit`**, чтобы убедиться,
что таймауты и параллелизм адекватны вашему каналу.

---

## Частые сценарии

```bash
# только RU-сегмент
python3 fw_test.py --segment ru

# только иностранный сегмент, без тестов передачи файлов
python3 fw_test.py --segment foreign --skip-download --skip-upload

# проверить конкретные порты
python3 fw_test.py --limit 100 --ports 443,80,22,3389,5432

# свои списки доменов из другой папки
python3 fw_test.py --domains-dir /opt/fwlists --output-dir /opt/fwlists/results

# медленный «вежливый» режим (пауза между доменами, мало воркеров)
python3 fw_test.py --workers 20 --delay 0.1
```

## Параметры командной строки

| Параметр | По умолчанию | Что делает |
|----------|--------------|------------|
| `--workers N` | `40` | число параллельных воркеров |
| `--timeout S` | `8.0` | таймаут на одну сетевую операцию (сек) |
| `--delay S` | `0.0` | пауза после каждого домена (вежливость к сайтам) |
| `--output-dir PATH` | `./fw_test_results` | папка для отчётов |
| `--domains-dir PATH` | `.` | где лежат `domains_ru.txt` / `domains_foreign.txt` |
| `--segment {ru,foreign,all}` | `all` | какой сегмент проверять |
| `--limit N` | `0` | ограничить число доменов на сегмент (0 = без лимита) |
| `--ports "a,b,c"` | `443,80,8080,8443,22,21,25,587,993,53` | TCP-порты для проверки |
| `--skip-download` | — | не тестировать скачивание |
| `--skip-upload` | — | не тестировать отдачу (upload) |
| `--log-level LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |

Полная справка: `python3 fw_test.py --help`.

---

## Что именно проверяется

Для каждого домена последовательно:

1. **DNS** — резолв имени (отдельно ловит блокировку DNS).
2. **HTTPS (443)** — полный TLS-хендшейк + HTTP-ответ.
3. **HTTP (80)** — обычный HTTP-ответ.
4. **Порты** — чистый TCP-коннект на остальные порты из `--ports`.

Отдельно (один раз за прогон):

- **Скачивание** — файлы 100 КБ и 10 МБ с Cloudflare, с замером скорости.
- **Отдача (upload)** — POST с телом 100 КБ и 1 МБ на httpbin.org, с замером.

> Важно: для теста файрвола **любой** полученный HTTP-ответ считается успехом
> (`OK`), даже код 4xx/5xx — значит, трафик дошёл. Блокировкой считаются только
> сетевые и TLS-ошибки.

## Категории результата

По ним видно характер фильтрации файрвола:

| Категория | Что означает |
|-----------|--------------|
| `OK` | соединение/ответ получены |
| `DNS_BLOCKED` | имя не резолвится (режется DNS) |
| `CONNECTION_REFUSED` | порт закрыт / RST на SYN |
| `CONNECTION_RESET` | соединение сброшено в процессе |
| `TIMEOUT` | таймаут — частый признак «тихого» DROP в файрволе |
| `TLS_ERROR` | ошибка TLS-хендшейка или сертификата |
| `HTTP_ERROR` | дошли до HTTP, но код ≥ 400 |
| `NET_UNREACHABLE` | сеть/хост недостижимы |
| `OTHER` | прочие ошибки |

## Отчёты

После прогона в `--output-dir` (по умолчанию `./fw_test_results/`):

- `fw_test_<дата_время>.csv` — подробно по каждой проверке: домен, сегмент,
  тип, порт, статус, HTTP-код, время отклика, объём, скорость, текст ошибки.
- `fw_test_<дата_время>_summary.json` — сводная статистика: доступность по
  сегментам, разбивка по категориям, по портам, медианные скорости.

Плюс краткий человекочитаемый итог печатается в консоль: проценты доступности
RU vs иностранный сегмент, какие порты открыты, скорости скачивания/отдачи.

## Свои списки доменов

Формат `domains_ru.txt` / `domains_foreign.txt`: **один домен в строке**,
строки, начинающиеся с `#`, игнорируются. Полные URL тоже допустимы — берётся
только хост.

```
# мой список
example.com
sub.example.org
1.2.3.4          # IP тоже можно
```

Готовые файлы собраны из рейтингового топ-листа (снимок популярности, не
«сегодняшний»). Домены реальные и резолвятся; если какой-то давно недоступен —
он просто попадёт в `DNS_BLOCKED`/`TIMEOUT` в отчёте. Для актуального рейтинга
можно взять свежий Tranco-список и заменить файлы.

---

## Замечания

- В длинном хвосте любого топ-листа попадаются adult/спам-домены — для проверки
  файрвола это просто хосты для коннекта, контент не загружается.
- Запускайте только против **своего** сервера и канала. Полный прогон создаёт
  большую исходящую нагрузку — это нормально для теста fw, но начинайте с
  `--limit` и при необходимости снижайте `--workers` / повышайте `--delay`.
